# Submission package — index & how to finish it

This folder holds the deliverables for the project submission. Three are built;
two more (the PDF and the source zip) are one command each and are listed below.

| Deliverable | File | Status |
|---|---|---|
| Project report (editable) | `report.docx` | ✅ built — **fill in details, then export PDF** |
| Project report (PDF) | `report.pdf` | ⬜ export from `report.docx` (command below) |
| Presentation slides + voiceover script | `slides.pptx` | ✅ built — voiceover is in each slide's **speaker notes** |
| Video demo instructions | `VIDEO-DEMO-GUIDE.md` | ✅ built — steps + exact commands |
| Source code README (how to use the code) | `../README.md` | ✅ already in the repo root |
| Source code zip | `source-code.zip` | ⬜ generate at submission time (command below) |

## 1. Finish the report — fill in details, then export the PDF

Open `report.docx` in Word / Google Docs / LibreOffice and fill in the
placeholders (shown as `____`):

- **Cover page:** institute/department, course, **Group No.**
- **Team table:** each member's **title** (Mr./Ms.), **mobile no.**, **email ID**
  (names, enrolment numbers and the individual-contribution column are already
  filled in).

Everything else — Introduction, Proposed System (with diagrams), Implementation
(tools, screenshots, comparison table), Conclusion, Bibliography — is complete.
The report is **Times New Roman 11pt, default margins**, as required.

**Screenshots:** the report embeds text renderings of the dashboard and query
output as Figures 2–3. If you want full-colour screenshots, capture them while
recording the demo and paste them into the dashed "paste screenshot here" box
(Figure 2a) and/or over Figures 2–3.

**Export to PDF** (last step, after the details are in):
- Word: *File → Save As → PDF*, or *File → Export → Create PDF/XPS*.
- LibreOffice: *File → Export As → Export Directly as PDF*, or on the command line:
  ```sh
  soffice --headless --convert-to pdf report.docx
  ```
- Google Docs: upload the .docx, then *File → Download → PDF*.

> The PDF isn't generated here because this machine has no LibreOffice/Word, and
> because it must reflect your filled-in names/mobiles/emails — so exporting is
> genuinely the right last step for you to do.

## 2. Slides + voiceover

`slides.pptx` is a 10-slide deck (title → motivation → pipeline → the two novelty
slides → coverage → demo → comparison → validation → conclusion). **The voiceover
script for each slide is in that slide's Speaker Notes** (View → Notes in
PowerPoint; the notes pane below the slide). Total narration ≈ 3–4 minutes.

Add the group number on slide 1 (`Group No.: ______`). Member names are already
on the title slide.

To record a narrated slide video: PowerPoint *Slide Show → Record*, then
*File → Export → Create a Video*.

To sanity-check the deck renders cleanly (optional, needs LibreOffice):
```sh
soffice --headless --convert-to pdf slides.pptx    # then open slides.pdf
```

## 3. Video demo

Follow `VIDEO-DEMO-GUIDE.md` — it has the full shot list, exact commands in
filming order, and an optional live two-machine variant. Target length 3–5 min.

## 4. Source-code zip

Generate a clean zip of the source at submission time (run from the repo root):

```sh
cd ~/projects/intrusion-detection-system
# commit any pending changes first if you want them included, then:
git archive --format=zip -o submission/source-code.zip HEAD
```

`git archive` includes only tracked files (no `node_modules/`, no build output,
no local logs), which is exactly what you want for a source submission. To include
uncommitted edits instead, zip the working tree while excluding junk:

```sh
zip -r submission/source-code.zip . \
  -x '.git/*' 'bin/*' 'submission/*' 'ids-alerts.jsonl' '*/node_modules/*'
```

## 5. Posting to the channel

Post each item **individually** (report .docx and .pdf, slides .pptx, the demo
video, the source zip, and the repo `README.md`) — do **not** wrap them in one
folder/zip, per the submission instructions. The `source-code.zip` is the only
zip, and it contains the code, not the other deliverables.

### Build/regeneration notes (for the team, not for submission)

The report and slides were generated by scripts in this folder (`gen-report.js`,
`gen-slides.js`) using the `docx` and `pptxgenjs` npm packages (installed here in
`node_modules/`). Edit a script and re-run `node gen-report.js` or
`node gen-slides.js` to rebuild — but once you've filled details into the `.docx`
/ `.pptx` by hand, edit those files directly instead, or your edits will be
overwritten on the next regenerate.
